# Meetup · Football Telegram bot

Запись на футбол в Telegram: свой голос, до 3 друзей, отмена записи, отметки об оплате переводом и наличными, подтверждение денег администратором. Данные и ID сообщений сохраняются в SQLite.

## Расписание (Europe/Moscow)

- Вторник 10:00 — публикация на среду.
- Четверг 09:55 — удаление (до лимита Telegram 48 часов).
- Пятница 11:00 — публикация на воскресенье.
- Воскресенье 10:55 — удаление пятничного сообщения и повторная публикация с теми же данными.
- Воскресенье 15:00 — удаление голосовалки. Оплаты и списки остаются в БД.

Во время перезапуска бот восстанавливает актуальное сообщение в пределах окна; предыдущий идентификатор сообщения хранится в БД. Telegram не позволяет удалить сообщение старше 48 часов. Если Telegram отклонит удаление, в журнал пишется ошибка; администраторам необходимо вручную очистить устаревший пост.

## Запуск на VPS

Нужен Docker с плагином Compose.

```bash
git clone https://github.com/AIestimGRO/meetup.git
cd meetup
cp .env.example .env
nano .env
mkdir -p data
sudo chown 10001:10001 data
docker compose up -d --build
docker compose logs -f --tail=100
```

Значения BOT_TOKEN (новый токен из @BotFather), CHAT_ID и ADMIN_IDS обязательны. Не загружайте .env в GitHub. Для оплаты можно задать PRICE_RUB (необязательно).

Для обновления:
```bash
cd meetup
git pull --ff-only
docker compose up -d --build
```

Откат: `git log --oneline`, `git checkout <SHA>`, `docker compose up -d --build`. Перед откатом сохраните копию `data/meetup.sqlite3`; новые записи в БД могут быть несовместимы со старой версией.

**Важно:** остановите прежний экземпляр бота перед включением нового, чтобы два процесса не использовали один Telegram-токен.

## Команды

- `/start` — описание;
- `/status` — текущая запись;
- `/payments` — панель подтверждения оплат (только ADMIN_IDS, в личке с ботом);
- `/publish_wednesday`, `/publish_sunday` — ручной старт (только ADMIN_IDS);
- `/close` — закрыть текущую голосовалку (только ADMIN_IDS).

Кнопка «Отметить оплату» открывает меню: отметка за себя, конкретного друга или всю компанию; отдельно выбирается «Перевёл» или «Наличными». Это **заявка об оплате**, а не автоматическое подтверждение. Только организатор может подтвердить полученные деньги через `/payments`. Если деньги отправляет другой игрок за чужую компанию, организатор может подтвердить соответствующие позиции вручную.

Бот должен быть администратором группы с правом удаления сообщений. Бот должен быть начат организатором в личном чате для команды `/payments`.

Для первичной проверки используйте отдельную тестовую группу и отдельный тестовый токен. 

## Версия 2.1: компактное меню и реквизиты

В главном сообщении теперь только запись и добавление друзей, кнопка «💳 Оплата» и «📞 Администратор поля». «Оплата» раскрывает дополнительные кнопки за себя, друга 1–3 и за всю компанию (перевод / наличные), а «⬅️ Назад к записи» возвращает главное меню.

«Администратор поля» показывает кликабельный телефон **+79653743566** с кнопкой возврата. Возможность немедленного открытия звонка зависит от Telegram-клиента.

Назначение получателя перевода (только ADMIN_IDS):

- В личном чате с ботом: `/set_receiver +79991234567 Иван`
- Или ответьте этой командой **в группе** на сообщение выбранного участника — имя бот возьмёт из Telegram-профиля (присутствие человека в группе проверьте самостоятельно)
- `/receiver` — посмотреть реквизиты
- `/clear_receiver` — удалить реквизиты

Телефон и имя получателя видны всем участникам группы, если открыт раздел «Оплата». Получатель должен согласиться на публикацию номера.

**Уточнение интерфейса:** Telegram inline-кнопки привязаны к одному общему сообщению, поэтому открытие меню меняет экран для всей группы, а не только для нажавшего. Для независимых персональных меню потребуется личный чат с ботом или Telegram Mini App.

### Обновление существующего контейнера

```bash
cd /opt/football-bot
git pull --ff-only
docker compose up -d --build
docker compose logs --tail=50
```

База SQLite расположена в `./data` и не удаляется при пересборке контейнера. При необходимости перед обновлением сделайте резервную копию БД, предварительно остановив контейнер.

## Автоматическое обновление кнопок после перезапуска

При запуске контейнера бот проверяет текущее московское окно голосования. Если активное сообщение уже существует и не требуется плановая перепубликация, он вызывает `editMessageText` для сохранённого `message_id` и обновляет клавиатуру на месте. Списки игроков и оплаты из SQLite не изменяются; второе сообщение не создаётся. Ошибки Telegram (например, сообщение было удалено вручную) записываются в Docker-логи.

## Устойчивость к нестабильной связи (v2.2)

- «− Отменить» удаляет только собственную запись, **друзья остаются**; можно добавить до трёх друзей вообще без личной записи. Удаление друга работает отдельно.
- При запуске и каждые 15 минут бот пытается сверить действующее голосование с Telegram; ошибка редактирования не удаляет данные SQLite. Восстановление после перебоев не гарантирует бесперебойную доступность Telegram.
- Ежедневная резервная копия базы в `data/backups/`, хранятся последние 14 копий на этом же VPS (это **не** внешнее резервное хранение).
- Если старое сообщение не удалилось, бот сохраняет его ID и **не создаёт второе** до успешного удаления.
- Если Telegram не вернул ответ на публикацию, бот не может знать, создано ли сообщение. Он устанавливает защиту `send_uncertain`, чтобы исключить дубли. Администратор проверяет чат: `/resolve_send` показывает инструкцию. `/resolve_send CONFIRM` (строго в личном чате) применяется только если сообщения точно нет; если Telegram успел опубликовать сообщение, потребуются ручная привязка ID или удаление сообщения перед снятием блокировки.
- При потере внешнего соединения API запись в чате может быть временно недоступна. Нажатия нельзя гарантированно восстановить, пока Telegram не доставит update.
- Для высокой надёжности рекомендуется выносить копии БД на другую машину и контролировать ошибки Docker-логов.

Перед обновлением текущего сервера:
```bash
cd /opt/football-bot
docker compose stop
cp data/meetup.sqlite3 data/meetup-backup-before-v22.sqlite3
git pull --ff-only
docker build --pull=false -f Dockerfile.offline -t meetup-football-bot:offline .
docker tag meetup-football-bot:offline meetup-football-bot:latest
docker compose up -d --no-build --force-recreate
docker compose logs --tail=50
```
